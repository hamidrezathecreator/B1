# Level 2 and 3 scene setup

Gameplay objects, interaction colliders, destinations and flow components are saved in the production scenes. Runtime setup does not spawn these objects or resolve targets by name. Renaming objects keeps their assignments intact.

## Level audio

- Each production scene has **Level Soundscape** with separate ambient and opening-dialogue sources. Level 1 dialogue starts 10 real seconds after scene startup. Level 3's state machine plays its assigned **Opening Dialogue** once and waits for it to finish before the launcher tutorial. Replace their clips independently in the Inspector.
- Level 1 **First Explosion Music** fades in on the first actual missile impact, survives the load into level 2, and fades out only when the elevator doors finish opening. Its volume and fade durations are on **Persistent Level Music**. Restarting level 1 or leaving level 2 clears the carried music.
- Level 2 uses separate **Elevator Audio**, tunnel loop music and tunnel ambient sources. The elevator ambient runs in the cabin; after both doors open it fades out while the tunnel loop and tunnel ambient fade in.
- **Military Tablet Lcd Ui / Option Sounds** contains three independent sources using `Sounds/LevelSounds/TabletToggleSound.mp3`. Each accepted change plays its own sound, including unchecking; repeated assignment of the same state is silent.
- All level soundscape clips use `Sounds/LevelSounds`. The fighter jet uses `FighterJetsound.mp3`; it immediately cuts the level 1 opening dialogue (including a pending delayed start). Its reaction dialogue starts one real second after the jet cue. Opening dialogues and ambience have independent sources.
- Checking the third tablet option after the doors open starts `Lvl2tolv3 transition.mp3` and fades out the level 2 loop. This music plays once in full, continuing through the scene load and underneath the level 3 opening dialogue. Leaving level 3 or restarting clears it. Unchecking cancels the scene countdown without restarting the music.

## Level 2

Select **Level 2 Flow** in `Scenes/Production/Lvl2_MissileTunnel.unity`.

- **Elevator Door Intro** references the cabin, doors, floor-button interactables, barrier, tablet, table, player, fade overlay and audio sources.
- **Elevator Boundary** stays active through fade, button waiting, travel and door opening. It is a child of the moving cabin. **Level Boundary** starts inactive and replaces it only after both doors finish opening. The enforcer follows the headset horizontally, including room-scale movement.
- Fade completion comes from the intro's actual fade routine. Only then are the floor buttons enabled. A single accepted press starts the ride; tablet progress cannot bypass the closed doors.
- **Elevator Door Intro > Elevator Button Order Voice** references the dedicated **Elevator Button Order Voice** source under **Level 2 Flow**. It plays `Sounds/Voices/Level2AfterElevatorButtonPressOrder.mp3` once when a floor-button press is accepted, alongside the ride. Repeated button events do not replay it, and disabling the intro stops it.
- Move **Player Spawn** inside the cabin to set the starting position. Move **Elevator Arrival** to set the cabin's destination. Keep the arrival outside the moving cabin hierarchy.
- Move the **Door 1/2 Open Pose** and **Floor Button Pressed Pose** anchors to edit the animation destinations. Keep these anchors beside their moving objects, not beneath them.
- **Tablet Path Start**, **Tablet Path Corner** and **Tablet Path Destination** define the route after the doors open.
- The tablet has its grab, rigidbody and three option trigger colliders in the scene. Its starting placement is preserved. Assign **Left Hand Root** and **Left Attach** on Tablet Grab Interactable; **Capture Left Hold Pose** updates the assigned attach anchor from the hold settings in Edit Mode.
- Transition waits for the elevator doors to open and all three options on the assigned tablet to be checked. Unchecking an option cancels the pending transition.

## Level 3

Select **Level 3 Flow** in `Scenes/Production/LVL3_MissileLaunch.unity`.

- **Level 3 Flow > Launcher Button Voiceovers** holds one **Launcher Tutorial Voice** for both buttons and a separate **Launcher Order Voice**. The state machine plays the tutorial once, waits for it to finish, then plays the order once. Both buttons become available after these voices finish. **Voiceover Source** is the dedicated 2D source on **Launcher Tutorial**. Empty voice clips skip playback.
- **Orchestrator** uses **Launch Buttons Only** for this level. Either button can be pressed first. Each launches its own missile once and immediately hides only its own card. The other button stays available, without repeating the narration. Both distinct buttons and both launch sequences must finish before **Auto Launcher Salvo** starts after **Delay After Tutorial Before Salvo**. Missile arrival is not required, and there is no interaction timeout. The controller hint remains until both buttons have been pressed.
- **Level 3 Flow > Tracker Pickup Voiceovers** holds **Tracker Tutorial Voice** followed by **Tracker Order Voice**. They start at **Path To Tracker Device**, after the drone strikes finish and its orbit starts. The tracker and path appear at that step; pickup progression waits for both voices to finish. No tracker narration plays at scene startup. The state machine owns all four voice cues, so button presses cannot replay them; disabling or restarting the sequence cancels its audio.
- Launcher and tracker tutorials use `B1_Document-Assets/Part 3/Part 3 _ Step 1.mp3` and `Part 3 _ step 2.mp3`, respectively. Their order clips are `Sounds/Voices/Level3_AfterFirstTutorialOrder_radio.wav` and `Level3_TrackerOrder_radio.wav`.
- **Automatic Launches** contains 23 scene missile projectiles, including all 21 `SM_Luncher2` launchers. Each copied launcher has its own Point A and Point B; its destination preserves the original launcher's local heading offset. The state machine launches them directly with random gaps between **Min/Max Delay Between Auto Launches**. The ten added copies are under **Additional Launchers**; move or rotate each **Launcher 01–10** parent to place its launcher and waypoints together. These copies initially overlap their source launcher for manual placement.
- Every level 3 projectile has **Continue Beyond Destination** enabled. The destination establishes its final heading; the missile keeps flying at arrival speed with its exhaust and audio until disabled, destroyed or reset.
- **Drone Root**, **Drone Flight** and **Drone Strikes** reference the existing drone and its two intact/wreck pairs. The strikes finish before the tracker pickup stage starts.
- Each drone strike spawns the same 400-metre condensation cloud as level 1. The pressure front triggers positional and rotational XR impact motion, haptics and pressure audio when it reaches the tracked headset.
- Both unit strikes and the tracked drone's destruction use the shared **Explosion 13** prefab. Each spawn activates the prefab so its particles face the main camera once, then keep that orientation during headset movement. Unit strikes preserve the optimizer's disabled particle systems.
- **Tracker Scope** and **Tracker Path Target** assign the weapon and guidance destination. The tracker has an authored grab collider, rigidbody, camera, target and missile launch origin.
- The entire tracker starts inactive and appears at **Path To Tracker Device**, after the strikes and drone orbit start. Lock-on is enabled after pickup. Its referenced **Scope Screen Material** retains the stereo-capable unlit display shader in builds; the feed uses a mono 2D render texture and recovers a lost graphics target. Both Android and Standalone renderers include the thermal pass. The shared grain include avoids reserved HLSL identifiers so the thermal shaders compile on D3D11.
- All 25 launch missiles use **Level 3 Flight Light**, which carries an occluded data-driven lens flare that follows and ramps with the exhaust light. The headset enables post-processing, and both renderer presets retain the required post-process resources.
- The flare uses the same normalized flicker as the point light, including the engine power ramp and shutdown. **Flare Intensity** and **Tremble Speed** are on the prefab's **Missile Launch Light** component; the animation runs in Play Mode.
- Both renderer presets include **XR Lens Flares**, which draws each eye into its own color slice and samples that eye's current depth slice. Each eye uses its own projection origin, including headset eye separation. The pipeline's built-in data-driven flare pass is disabled to prevent duplicate eye-zero draws; keep the renderer feature enabled instead. The feature retains the shader through its serialized reference for builds.
- To replace its appearance, select `ThermalMonitor/Materials/Lvl3MissileFlare.asset`, expand **Elements > Element 0**, keep **Type = Image**, and assign **Flare Texture**. The supplied `MissileFlareSoftStar.png` is an alternative with a compact warm core, soft falloff and subtle diffraction streaks. This asset is shared by all level 3 missiles.
- After assigning a transparent PNG, select the flare data asset and use **Assets > Prepare Alpha For Additive Lens Flare**. Additive blending ignores texture alpha, so this command bakes alpha into the image's RGB in linear light and assigns a separate emission texture. The original image stays editable. The emission texture uses uncompressed RGBA32 on Android and Standalone, with mipmaps for smooth distant flares. Running the command again regenerates from the original image, without applying alpha twice.
- Keep **Use Occlusion** enabled on the prefab's **Lens Flare (SRP)** component. Its 2.5-centimetre source radius and offset prevent the old one-metre probe from looking through nearby geometry. Occlusion uses rendered depth, so opaque meshes do not need colliders; transparent materials must write depth to act as blockers.
- **Xr Level Play Setup** references the player spawn, ground, teleport rays, cameras, tutorial button adapter, all 25 launch projectiles, audio and feedback recipients. It configures XR and presentation; the state machine owns progression. Ground colliders and teleportation areas exist in the scene.

State machine Inspector shortcuts explicitly skip gameplay waits for testing. Normal gameplay waits for the assigned interactions. Missing required assignments report errors and block progression. Path graphics, hints, scope rendering, missiles and impact effects remain runtime presentation.
